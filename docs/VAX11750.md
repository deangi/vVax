# Conversion plan: MicroVAX II (KA630 / UV2) → VAX-11/750 (KA750)

**Status:** V0.7.34 on branch `vax-11750`. C0–C6 and C4 (`uda0`/`ra0`/`root on ra0a`)
met on GENERIC. **C8 closed (29 Aug 2026):** single-user `#` works; `/etc/rc`
cannot finish on 8 MB RAM. Ash SIGSEGVs sourcing `/etc/rc.subr` because libc
does a **1 MB P1 heap grow** (`LNV VA=7F400000`) while UVM has ~3.2 MB
managed, ~32 pages min-free, and **no swap yet** (`swapctl -A` is later in
`rc`). Not CVTLD / not an ISA miss. ESP32 cannot allocate more than 8 MB
guest RAM; changing `rc` is out of scope. C9: console TU58 present, no
cartridge; `ctuattach` RET plant stays. C7: F/D wired + ACCS=1, still not
proven on a full `rc` (`ps` / CVTLD). EMOD/POLY still reserved.
**C10** (VMS conversational boot) is planned, not met: last VMS drop is
V0.7.6 (`os=vms` xxboot + I-fetch-0 SYSBOOT memcpy plant; HALT
`PC=000FFEC4` without it). Product target on `main` remains MicroVAX II.
Still no VMB / KA750 console ROM. `[system] os=` (`netbsd` default, or
`vms`) is a host boot-path flag, not a SID lie.

**Results (V0.7.0 USB):** selftest `dma=UBA/18-bit` PASS; xxboot

## 1. Goal

**vVax-as-11/750** means a KA750-class CPU on CMI + one DW750 Unibus adapter,
not a Q22 MicroVAX with the SID byte patched.

| Piece | Meaning for v1 |
|-------|----------------|
| CPU type | SID type **2** (`VAX_TYP_750`). Match Open SIMH: `VAX750_SID \| VAX750_MICRO \| VAX750_HWREV` → **`0x0200639C`** (type 2, ucode 99, hw 156). |
| Console | KA750 **console DL** via IPRs `RXCS/RXDB/TXCS/TXDB` (32–35) into the existing host VT100/Telnet/USB path. Not KA630 ROM conspage. Not a Unibus DZ as the system console. **C9:** console TU58 IPRs 28–31 always present, no cartridge (`RSP_MOD_NOC`). Stock GENERIC still needs the `ctuattach` RET plant (`ka750_conf` → `bufq_alloc` before `bufq_init`). |
| Bus | **CMI** nexus space (SIMH `0xF00000+`) + **DW750 UBA** (SIMH `0xF30000`, maps, Unibus I/O page at `0xFFE000`). Not Q22 at `0x20000000`. |
| Disk | **UDA50-class MSCP** on Unibus CSR **0172150** (reuse `vax_mscp` protocol). Not Massbus RP. Not RQDX3 Q22 packing. |
| Boot firmware | Keep host **FROM750-style xxboot** (`vax_boot`: MSCP LBA 0–15, `PC=0x0C`, R6=ROM-read stub). That is **NetBSD `xxboot` / `read750` ABI**, not DEC KA750 console ROM. Do not invent or commit `vax_ka750_bin_*.h` dumps. **C10** uses the same loader with `[system] os=vms` (no NetBSD CD ELF reloc / hopp / fingerprint / niclose). No VMB. |

### First bring-up OS

**NetBSD/vax 10.1 GENERIC** on the current MSCP image
(`netbsd101-boot.dsk` / install ISO). GENERIC already has `options VAX750`,
`cmi0 at mainbus0`, `uba* at cmi? tr?`, and `uda* at uba? csr 0172150`.

VMS is why a 750 is interesting (compatibility mode, D-float, Unibus UDA).
**NetBSD GENERIC remains the first bring-up OS and the live C8 work.**
**C10** is conversational VMS on this branch with a **user-supplied** pack
(`[system] os=vms`). Hobbyist kits stay out of tree. C10 does not change
[`TARGET.md`](TARGET.md) (MicroVAX II on `main`).

## 2. Why 11/750 vs keep MicroVAX II

Honest tradeoffs. The current guest **already thinks it is a MicroVAX II**
(`cpu0: KA630, UV2`, `uba0 at mainbus0: Q22`). Changing SID is not a small
compat tweak; it is a different machine.

| Keep KA630 / UV2 | Move to KA750 / 11/750 |
|------------------|-------------------------|
| Phase 6 is far along: `/boot`, GENERIC, FFS, `init`/`sh`. Known CSR aliases `0x20001C68` / `0x20001468`. | Throws away Q22 map/window, KA630 SIE/NVR/conspage, MicroVAX MCHK frame. New CMI+UBA bring-up. |
| ISA subset matches what we implemented (Tier B integer/`IG_BASE` + C7 F/D; EMOD/POLY reserved). Compatibility mode is reserved (current `PSL_CM` check). | Full 11/750 ISA expects **F+D float** and **packed decimal**; compatibility mode is architected. Userland `ps` already hits `CVTLD` (`0x6E`). |
| Q22 is 22-bit; we already paid for the 4 MiB ring alias and `0x30000000` window MCHK. | Unibus is 18-bit through 512 map regs. The Q22 alias hack must **not** travel. Smaller map table (2 KiB vs 32 KiB). |
| No proprietary ROM today (FROM750 xxboot). | Same: still no DEC ROM. 750 console ROM at `0xF20400` stays unimplemented. |
| SIMH comparison today is **KA655 CVAX** (`ka655`), which is *not* UV2 — that mismatch is exactly the Phase 6 `xot` investigation. | Comparison target becomes Open SIMH **`vax750`**, which is the same CPU type. Better apples-to-apples than UV2 vs CVAX. |
| VMS rejected a SID-only lie on KA630 (`%BOOT-F-Unknown processor`). | SID/CPU type change is in scope here because the *machine* changes. |
| Contained Q22 story; fits the original [`docs/research/hardware.md`](research/hardware.md) rationale. | CMI+UBA+nexus is more code, but 8 MB RAM is a legal 750 size (SIMH allows 8M; historical max ~8–15 MB). ESP32 PSRAM still fits. |

**NetBSD GENERIC does not need a custom `ident` to know about 750**, but it
**will not** keep printing `KA630` / `Q22`. The same `/netbsd` binary probes
`findcpu()` from SID and then attaches `cmi` instead of Q22 `uba0 at mainbus0`.
If CMI/UBA are missing, autoconf idles without `uda0` — same class of failure
as V0.6.19, on a different bus.

Recommendation: convert **because** you want a 750 (VMS-shaped ISA, Unibus
UDA, honest SID), not because it will magically finish Phase 6. See §6 for
`xot`.

## 5. Phased conversion

### Decision: in-place vs dual-machine flag

**Recommend: compile-time model, one machine per firmware image.**

```c
// config.h — when implementation starts, not now
// #define VAX_MODEL_KA630  630
// #define VAX_MODEL_KA750  750
// #define VAX_MODEL        VAX_MODEL_KA750
```

Not a runtime switch. Not two guests in one `.bin`.

| Option | Verdict |
|--------|---------|
| In-place replace only | Simple, but you lose the KA630 firmware that almost reaches multiuser. Bad while `xot` is unexplained. |
| Dual-machine **in one flash** | Q22 maps (32 KiB) + UBA + two MCHK paths + two boot plants. Huge App is 3 MB (`sketch.yaml` `app3M_fat9M_16MB`); code size might fit, PSRAM/IRAM and maintenance will not. |
| **`VAX_MODEL` ifdeffed, one image** | Switch with a rebuild. KA630 stays a regression firmware. Dead code stripped. Matches ESP32 flash/RAM and one-guest mental model. |

Default in git can stay KA630 until a conversion branch is ready to flash;
the first 750 commit sets `VAX_MODEL_KA750` on that branch only.

### Host constraints (do not change)

- S1 not identity-mapped
- `VAX_CLOCK_WARP_DEFAULT 0`
- `VVAX_STEP_BATCH 10000`
- `VVAX_DIAG_LEVEL 0`
- No relocbase / reserved-REI PSL “fixes”
- No `APP_VERSION` bump in the plan; bump only when a real 750 drop is flashed

### Phases, dependencies, exit criteria, flash gates

**Do not flash a SID-only build** and expect GENERIC to keep using Q22
`0x20001C68`. Type 2 takes `ka750` / `cmi0`; Q22 `uba0 at mainbus0` will not
attach.

| Phase | Work | Depends on | Exit criteria | Do not flash until… |
|-------|------|------------|---------------|---------------------|

| **C1** | SID `0x0200639C`; ACCS/CADR/TBDR/MCESR/CMIE/CSRS stubs; stop decoding `0x20040004` / `0x200B8000` / `0x20088000` on 750. | C0 | `/boot` or a tiny SID print shows type 2. Self-test still `vVax OK`. | Kernel is expected to autoconf (it will look for CMI). |

## 6. Risks

1. **GENERIC dmesg will not say `cpu0: KA630, UV2`.** Expect KA750 + `cmi0`.
   No custom kernel required **if** CMI/UBA/UDA probe. A trimmed `ident`
   `VAX750` kernel is only a last resort to skip Q22/DZ/QE probes (`dhu0
   didn't interrupt`, `qe` `delay()`), not to fake CPU type.

2. **Unibus MSCP ≠ Q22 uda.** Same octal CSR **0172150**, different physical
   window and map. Reusing `csr_in_io_page` (`pa & 0x3FFFE000 == 0x20000000`)
   will miss `0xFFF468`. The V0.6.19 dual-alias trick is KA630-specific.

3. **8 MB RAM is OK** for an 11/750 (SIMH 8M; NetBSD 10.1 GENERIC ran on
   ~8 MB-class UV2 already). `/boot` at `0x7A0000` stays a Freenove PSRAM
   issue, not a 750 issue.

4. **`xot` may persist.** How to test:
   - Boot **the same** `netbsd101-boot.dsk` on Open SIMH **`vax750`** (not
     `ka655`). If SIMH 750 prints packed `export` and no `xot`, the bug is
     not “must be CVAX.” If SIMH 750 also `xot`s, it is image/userland, not
     UV2.
   - On vVax-750, if SIMH 750 is clean and we still `xot`, it is the
     interpreter (flags, `movb`, CTLESC path) — continue Phase 6 tracing,
     do not “fix” by SID.

5. **MCHK format.** UV2 12-byte block vs 750 40-byte `mc5_bcnt==0x28`. Wrong
   frame → `ka750_mchk` panic or corrupt REI. `badaddr` during nexus probe
   will fire early.

6. **`/boot` device type.** Type 1 (780) made `/boot` invent `devtyp` from
   R0 (`Can't open device type 24`). Type 2 is the FROM750 path; still
   confirm `R0=17` (UDA) and Unibus CSR in R2. Do not keep `R1=0x20000000`
   without a SIMH/NetBSD citation.

7. **Console IPL livelock** (V0.6.11 `{IE AND DONE}` edge) still applies;
   gencons uses the same CSRs.

8. **Nexus IRQ vs UQSSP `0x1FC`.** Copying IPL 14 delivery without UBA
   `int_ack` will miss `udaintr` or steal the wrong vector.

9. **Flash size.** Huge App 3 MB; one model is fine. Do not ship both buses
   “just in case.”

**C10 (VMS, `[system] os=vms`, user pack on MSCP A — not in-tree):**

1. USB: `boot: VMS (os=vms; xxboot block loader, no VMB)` and Unibus
   `R2=0x00FFF468` (not Q22 `0x20001C68`)
2. No `%BOOT-F-Unknown processor` (SID type 2)
3. No unexpected MCHK at `0xF20000` / `0xF80000` (V0.7.4 class)
4. `MCTL mcsr2=` with CS64 (`0x01011555` class) — not SYSBOOT parked at
   `0xFFEC4` because slots looked like 256 KiB (V0.7.5)
5. Execution past `PC=000FFEC4` **without** treating the V0.7.6 I-fetch-0
   memcpy as the architecture
6. Console: `SYSBOOT>` and/or VMS startup through `Username:`
   (match Open SIMH `vax750` on the same pack)

Failure signatures (expected if a phase is skipped):

- Still `KA630, UV2` → SID still `0x08……`
- `Can't open device type 24` → SID/bootregs wrong (known type-1 failure)
- No `cmi0` / halt in `findcpu` → SID not type 2 or nexus space dead
- `uba0 at mainbus0: Q22` → still on UV2 board type
- No `uda0` → Unibus CSR/map/IRQ (old V0.6.19 class)
- MCHK panic in `ka750_mchk` → UV2 frame or bad nexus timeout
- `%BOOT-F-Unknown processor` → SID still type 8 (C10, not C8)
- HALT `PC=000FFEC4` zeros → SYSBOOT still 1 MiB-linked / copy never ran
- `boot: VMS relocate` only, no `SYSBOOT>` → still the V0.7.6 plant (not C10)

`xot` after `sh` is **not** a C8 gate; record it vs SIMH `vax750` and keep
it on the Phase 6 track. C10 does not close xot or C8.

## Appendix B — SID encoding (citation)

Open SIMH `vax750_defs.h`:

- `VAX750_SID = (2 << 24)` → `0x02000000`
- `VAX750_MICRO = (99 << 8)` → `0x00006300`
- `VAX750_HWREV = 156` → `0x9C`
- Combined **`0x0200639C`**

NetBSD `sid.h`: `VAX_TYP_750 = 2`, `VAX_BTYP_750 = 0x02000000`. UV2 remains
`VAX_TYP_UV2 = 8`, `VAX_BTYP_630 = 0x08000001` (this tree’s current SID).

Current vVax SID must **not** stay `0x08000001` on a 750 bus. Changing SID
without the bus is how you get a confused `/boot`; changing the bus without
SID leaves GENERIC on the Q22 attach path.
